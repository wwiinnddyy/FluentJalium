# ## 这些读数支持什么
# - SetCursorPos 级别的真实指针移动会置起 UIElement.IsMouseOver（触发器 owner 就是 UIElement，
#   不是被遮蔽的副本），进而让样式触发器把悬停刷交给控件，最后落到像素（run 5 的 hover2/part 两行）。
# - 带 TransitionProperty="Background" 的模板面在首帧之后仍然会采纳新的刷对象（swap 的 transitioned 行），
#   和没有过渡的模板一样（plainAdopted=True），所以状态换刷不依赖"就地改色"这一条通路。
# - plain（无过渡）模板只有一个裸 Border、没有文字与焦点框，所以 distinct=2；带过渡的按钮 distinct=7，
#   多出来的 #00E300/#00E200/#000000 与休息位的 #E300E3/#E200E2/#000000 同结构，是文字与边框的抗锯齿，
#   不是混合中间值——所以 distinct 数量不能当"是否停在过渡中"的判据。
#
# ## 这些读数不支持什么（我一度误读的地方）
# - run 3/4 的"属性绿、像素品红"不是框架缺陷：那两次 cursor 行显示物理光标在推帧期间自己走掉了
#   （asked=1237,634 而 actual=1478,702 / 4,4），hover2 读到 IsMouseOver=False 就是这个原因。
#   同一时间有人在动这只鼠标，所以这个通路不能进常跑闸口。
# - run 5 的 invalid 行 #E482E4（品红↔绿的中间值）证明过渡动画真的在跑：固定帧数捕获会采到混合中的画面。
#   判据必须是"重复捕获直到两张图一致"，不是"等 N 帧"。
# - 按下/释放分支（IsPressed、橙色 FFA500）没有任何读数：需要 SendInput 真按键，会点到用户桌面上
#   任何东西，未经同意不运行。键盘（空格/回车激活）与触摸路径同样未测。
