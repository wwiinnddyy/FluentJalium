[C] 间距与步进：Spacing 的正负不对称
spacing: code unset: read-back=0 desired=48x16 pitch=16
spacing: code 8: read-back=8 desired=64x16 pitch=24
spacing: code 24: read-back=24 desired=96x16 pitch=40
spacing: code -10: read-back=-10 desired=48x16 pitch=16
spacing: markup Orientation=Horizontal Spacing="8": type=StackPanel orientation=Horizontal read-back=8 desired=64x16 pitch=24
spacing: pitch with Spacing=8 + Margin=-8,-8,0,0: pitch=16 cell0.X=-8 desired=40
spacing: pitch with Spacing=8 + cells 34 wide, later cells Margin.Left=-18: pitch=24 cell4.X=96 desired=130 (5*34+4*8=202, compensated=130)
spacing: Segoe Fluent Icons 32 set glyph: measured=34x34 arranged=306.286x201.143
spacing: Segoe Fluent Icons 32 unset glyph: measured=34x34 arranged=306.286x201.143

读法：三格 16 宽。间距 0/8/24 时 pitch 16/24/40 —— 正数照加。间距 -10 时属性读回 -10，
但 desired 仍是 48（=3×16）且 pitch 仍是 16：负号被留下、被排布当成 0。这是第三类静默失效
（前两类是 {x:Bind} 与 Clip），而且是最阴的一种：属性读回证明你写了。
同一份 -10 改成"后续格 Margin.Left=-18"时 pitch 实测 24、第五格落在 X=96、行宽从 202 收到 130 —— 负边距真的动布局。
32 号 Segoe 星形实测步进 34（arranged 那一对是宿主格子撑出来的，不是字形的盒子，别读它）。

裁剪题必须捕获更宽的祖先：RenderTargetBitmap 是按目标尺寸出的，裁没裁都填满那张图。

[E] 缩放：0.5 真的落墨，但"捕获目标自己"看不见
transform: control, no transform: accent=3600 painted=3600
transform: origin read-back=0.5,0.5 type=ScaleTransform: accent=3600 painted=3600 (900 if the 0.5 reaches the ink, 3600 if not)
transform: 60x60 at 0.5 seen through a 200x200 ancestor: x=15..44 y=15..44 accent=900
transform: same box with no transform, same ancestor: x=0..59 y=0..59 accent=3600

读法：前两行差点把结论写错。第三行才说清楚：0.5 关于 0.5,0.5 真的缩小了墨 —— 从 200×200 祖先里看，
60 的块只占 x=15..44、900 像素，没有变换的对照是 x=0..59、3600 像素。
所以"捕获目标自己"对目标自身的 RenderTransform 是瞎的（与 [D] 最后一行同一条仪器账），
uniform 的读数先怀疑仪器，这次也是仪器。上游的 0.5 因此可以照搬成 RenderTransform。
