[E] markup and template readings, from the test iterations that found them
  1. <ControlTemplate.Triggers> written inside the template's root element is a parse error, not a silent drop:
     XamlParseException: Cannot find attached property setter for: ControlTemplate.Triggers. It has to be a direct
     child of <ControlTemplate>. Three templates in Styles/PipsPager.jalxaml hit this before the first green run.
  2. A <Setter TargetName="..."> inside a Style's setters does not reach the template part. The selected pip kept
     the 3.8 dot its base style gave it. The same write from a ControlTemplate.Triggers arm works, which is how the
     focus outline of a button is drawn today. Selected/normal therefore switch two drawn dots by Visibility through
     a trigger on the pip's Tag, and the styles carry only the brushes.
  3. Two <Ellipse> siblings directly inside one <Border> in a template leave the Border with no named child at all:
     Named(pip, "NormalDot") returned null while RootGrid resolved. Wrapped in a <Grid>, both parts are found.
     (No parse error, no warning - the parts simply were not there.)
  4. Clamping the scroll viewport from the realized containers' DesiredSize starves itself: UpdateViewport ran
     before anything was measured, and the _pipHost.SizeChanged that would re-run it never arrived again, because
     the host's arranged width is what the clamp limits. Reading: MaxWidth stayed 12 with two pips in the row and
     the second pip painted no ink. The footprint the control itself writes onto each container is now the input.
  5. The DP changed callback fires for a write of the value that is already set, with OldValue carrying the rejected
     value. That is what made the first version of the clamp raise SelectedIndexChanged twice for a second
     out-of-range write.
  6. An unbounded row (NumberOfPages=-1) has to be regenerated on every selection change, and the grow-only rule
     cannot ask the live list how big it was: PipCount saw an emptied list and shrank eight pips back to five.
  7. In Light the pip token is #5E000000, so its packed RGB is the same key as the host window's black backdrop:
     PixelKey(brush) counted 105966 pixels in a 9600 pixel subject, and adding a pip changed nothing at all. On a
     white surface the dot lands on #B5B5B5 and the same delta measures 19 pixels for one selected pip, then grows
     again for the second. Counts are read as histogram deltas between captures of one hosted element; hosting a
     second element in the same window leaves the first one in front of the capture.
  8. ((IInvokeProvider)new ButtonAutomationPeer(disabledButton)).Invoke() throws
     InvalidOperationException: Cannot invoke a disabled button - so the edge-of-range disable rule is assertable
     through the pattern rather than only through IsEnabled.
